# 实时流式翻译产品规格

## 产品目标与边界

本规格将已批准的 `INT-001` 至 `INT-006` 转化为可观察、可验收的产品行为：会议期间，浏览器采集发言人语音，使用客户指定 Azure Foundry STT 服务持续转写并自动检测源语言，再使用客户指定的大模型将识别结果持续翻译为中文并实时显示为字幕，使需要中文字幕的参会者及时理解发言。

范围限于会议中的浏览器语音采集、实时流式转写、源语言自动检测、中文翻译和字幕展示。源语言覆盖客户指定 Azure Foundry STT 服务可自动检测的全部源语言。Teams 仅为连续字幕体验参照，不属于集成对象。会后全文、录音、字幕归档或导出，中文以外的目标语言，会议或参会者管理，以及人工翻译、校订或审核均不在范围内。

`INT-006` 是客户已批准约束：语音转文本与源语言自动检测使用客户指定 Azure Foundry STT 服务，中文翻译使用客户指定的大模型。本规格原样保留该约束，不进一步选择架构、接口、模型、协议、运行环境或其他实现细节。

## 参与者与权限

- **发言人**：提供会议语音；不承担字幕控制职责，也没有获批准的管理权限。
- **需要中文字幕的参会者**：查看中文字幕，并可手动发起、停止和重新发起实时字幕流程。
- **浏览器设备许可**：浏览器取得语音输入许可是采集前置条件；它不是产品角色或账户权限。
- 当前没有获批准的账户体系、角色分级、会议管理或参会者管理要求。

## 用户故事

### US-001 会议中查看连续中文字幕（优先级：未指定）

作为需要中文字幕的参会者，我希望在发言人讲话期间持续看到由其语音转写并翻译得到的中文字幕，以便在会议进行时理解发言，而不是会后才获得结果。（`INT-001`、`INT-002`、`INT-003`、`INT-005`，`direct`）

### US-002 自动适配获批范围内的源语言（优先级：未指定）

作为需要中文字幕的参会者，我希望产品自动检测发言人的源语言，并覆盖客户指定 Azure Foundry STT 服务可自动检测的全部源语言，以便无需预先选择源语言即可查看中文翻译。（`INT-001`、`INT-004`、`INT-005`，`direct`）

### US-003 控制实时字幕流程边界（优先级：未指定）

作为需要中文字幕的参会者，我希望能够手动发起、停止并在停止或中断条件消除后重新发起实时字幕流程，以便明确浏览器何时开始和结束采集，并继续处理后续发言。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该控制时，已批准的浏览器采集没有可判定的启停边界，一次停止或中断后能否处理后续发言也不确定。）

## 功能需求

- **FR-001**：实时字幕流程处于运行状态时，产品必须通过浏览器采集发言人语音，并使用客户指定 Azure Foundry STT 服务持续形成流式转写结果。（`INT-003`、`INT-006`，`direct`）
- **FR-002**：产品必须使用客户指定 Azure Foundry STT 服务自动检测输入语音的源语言；接受范围为验收时该服务实际可自动检测的全部源语言。（`INT-001`、`INT-004`、`INT-006`，`direct`）
- **FR-003**：产品必须使用客户指定的大模型将范围内源语言的识别结果翻译为中文，并在会议期间以字幕形式持续展示。（`INT-001`、`INT-005`、`INT-006`，`direct`）
- **FR-004**：参会者手动发起实时字幕流程后，产品必须进入运行状态并开始执行 `FR-001` 至 `FR-003`。（`INT-003`，`closure`；缺少明确发起行为时，浏览器何时开始采集和处理会议语音不确定。）
- **FR-005**：参会者手动停止实时字幕流程后，产品必须停止采集，并且不得再基于停止后的语音产生新字幕。（`INT-003`，`closure`；缺少停止行为时，已批准的浏览器采集没有终止边界，停止后是否继续采集或产生字幕不确定。）
- **FR-006**：当语音无法被采集，或转写、语言检测、翻译中的任一步骤无法继续时，产品必须呈现当前无法继续产生字幕的可观察状态，不得将中断静默表现为仍在正常处理。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该状态时，参会者无法区分正常等待与流程中断，实时中文字幕行为在错误情况下不确定。）
- **FR-007**：停止后，或中断条件消除后，参会者必须能够手动重新发起实时字幕流程；后续有效语音按 `FR-001` 至 `FR-003` 处理，不要求补发停止或中断期间的内容。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少重新发起行为时，一次停止或中断后已批准流程能否继续服务后续发言不确定。）

## 产品质量要求

- **NFR-001**：对流程运行期间连续出现的有效语音，字幕必须在会议仍在进行时持续产生，而非仅生成单次结果或延迟到会后批量提供。（`INT-001`、`INT-002`，`direct`）

除上述实时、连续体验外，当前没有获批准的额外产品质量要求或数值阈值。

## 领域术语

- **实时字幕流程**：从参会者手动发起，到参会者手动停止或发生中断期间，将语音持续转写、翻译并展示为字幕的业务过程。
- **客户指定 Azure Foundry STT 服务**：`INT-006` 指定用于语音转文本和源语言自动检测的服务；本规格不进一步规定其实现方式。
- **客户指定的大模型**：`INT-006` 指定用于将识别结果翻译为中文的能力；本规格不进一步规定具体模型或调用方式。
- **覆盖语言范围**：验收时客户指定 Azure Foundry STT 服务实际支持自动检测的全部源语言。
- **识别结果**：客户指定 Azure Foundry STT 服务由输入语音形成、可供翻译的转写内容。
- **有效语音**：具备采集条件，且能够被客户指定 Azure Foundry STT 服务转写并自动检测为覆盖语言范围内源语言的语音。
- **中断**：采集、转写、语言检测或翻译无法继续，因而不能继续产生字幕的状态。

## 前置条件与触发条件

- 会议正在进行，发言人能够提供语音，需要中文字幕的参会者已进入浏览器中的实时字幕使用场景。
- 浏览器具备可用的语音输入，并已获得采集所需的设备许可。
- 客户指定 Azure Foundry STT 服务和客户指定的大模型可用于本次流程；验收方能够确认该 Azure Foundry STT 服务实际支持自动检测的完整源语言集合。
- 参会者手动发起流程触发采集、转写、语言检测、中文翻译和字幕展示；手动停止触发终止行为；停止后或中断条件消除后，手动重新发起触发后续语音处理。

## 行为模型

### US-001 会议中查看连续中文字幕

- **正常路径**：流程运行期间，产品采集语音，使用客户指定 Azure Foundry STT 服务持续转写和自动检测源语言，使用客户指定的大模型翻译为中文，并在会议进行时持续展示字幕。（`FR-001`、`FR-003`、`NFR-001`、`AC-001`、`AC-003`）
- **替代路径**：同一流程中的后续有效语音继续形成后续字幕，无需逐段重新发起。（`NFR-001`、`AC-003`）
- **边界路径**：参会者停止流程后，不采集停止后的语音，也不产生基于该语音的新字幕。（`FR-005`、`AC-005`）
- **错误路径**：任一处理步骤无法继续时，呈现流程中断状态。（`FR-006`、`AC-006`）
- **恢复路径**：条件消除后，参会者重新发起流程，后续有效语音恢复处理，不补发中断期间内容。（`FR-007`、`AC-007`）

### US-002 自动适配获批范围内的源语言

- **正常路径**：输入覆盖范围内任一源语言的有效语音，无需预选语言即可自动检测并输出中文字幕。（`FR-002`、`FR-003`、`AC-002`）
- **边界路径**：覆盖集合以验收时客户指定 Azure Foundry STT 服务实际支持自动检测的完整语言集合为准，不以预设固定语言清单替代。（`FR-002`、`AC-002`）
- **错误与恢复路径**：语言无法被检测或翻译无法继续时进入中断；条件消除并重新发起后处理后续有效语音。（`FR-006`、`FR-007`、`AC-006`、`AC-007`）

### US-003 控制实时字幕流程边界

- **发起路径**：未运行时，参会者手动发起，流程进入运行状态并开始处理后续语音。（`FR-004`、`AC-004`）
- **停止路径**：运行或中断时，参会者手动停止，流程进入已停止状态。（`FR-005`、`AC-005`）
- **重新发起路径**：已停止时或中断条件消除后，参会者手动重新发起，流程进入运行状态并处理后续语音。（`FR-007`、`AC-007`）

## 业务状态、业务数据规则与不变量

### 业务状态

1. **未启动**：尚未手动发起，不采集语音。
2. **运行中**：已手动发起，持续接收并处理语音，可产生中文字幕。
3. **中断**：采集、转写、语言检测或翻译无法继续，并呈现可观察状态。
4. **已停止**：已手动停止，不再采集语音或产生基于停止后语音的新字幕。

允许的转换为：未启动经手动发起到运行中；运行中到中断或经手动停止到已停止；中断经手动停止到已停止，或在条件消除后经手动重新发起到运行中；已停止经手动重新发起到运行中。

### 业务数据规则与不变量

- 每条中文字幕必须源自流程运行期间采集的语音及其识别结果。
- 字幕目标语言固定为中文；源语言由客户指定 Azure Foundry STT 服务自动检测，不要求参会者预选。
- 可接受的源语言必须属于验收时客户指定 Azure Foundry STT 服务实际可自动检测的完整语言集合。
- 转写和源语言自动检测必须使用客户指定 Azure Foundry STT 服务；中文翻译必须使用客户指定的大模型。
- 字幕仅承担会议期间实时展示；不承诺会后保留、归档、导出或补发。
- 未启动、已停止或中断状态下不得将流程表现为仍在正常采集并产生字幕。

## 错误与恢复行为

- 浏览器未取得语音输入许可、语音输入不可用或采集失败时，必须呈现无法继续产生字幕的状态。
- 客户指定 Azure Foundry STT 服务无法继续转写或检测源语言，或客户指定的大模型无法继续翻译时，必须呈现中断状态；不得以未经处理的内容冒充中文字幕。
- 对不属于覆盖语言范围或无法检测语言的语音，不要求生成中文字幕，按无法继续处理的中断行为处理。
- 条件消除后，由参会者手动重新发起流程处理后续有效语音；不承诺恢复或补发停止或中断期间的内容。

## 安全、隐私与可访问性行为

宪章“三、数据安全”要求保护会议内容和凭据，但未直接规定可从已批准 Intent 派生的具体用户可见产品行为。当前没有获批准的额外安全、隐私或可访问性产品要求，因此本规格不新增 NFR、等级、权限行为或验收门禁。

## 性能、可靠性与其他质量边界

已批准范围仅要求 `NFR-001` 所述会议期间持续产生字幕的可观察结果，未批准具体响应时限、刷新频率、准确率、可用率、恢复时限、并发容量或正式质量等级。

## 成功标准

- **SC-001**：在会议进行期间，覆盖范围内的有效发言形成持续展示的中文字幕，使参会者无需等待会后结果即可阅读。（`INT-001`、`INT-002`、`INT-005`，`direct`）
- **SC-002**：验收时客户指定 Azure Foundry STT 服务实际可自动检测的每一种源语言均属于产品接受范围，且无需预选源语言即可进入中文翻译流程。（`INT-001`、`INT-004`，`direct`）
- **SC-003**：连续有效发言产生连续字幕，而非只产生单次结果或会后批量结果。（`INT-002`，`direct`）
- **SC-004**：参会者手动发起后，流程进入运行状态并开始处理后续有效语音。（`INT-003`，`closure`；缺少该标准时，浏览器开始采集的边界无法验收。）
- **SC-005**：参会者手动停止后，流程不再采集后续语音或产生基于该语音的新字幕。（`INT-003`，`closure`；缺少该标准时，浏览器采集的终止边界无法验收。）
- **SC-006**：流程无法继续时，参会者能够区分中断与正常处理。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该标准时，错误情况下的实时字幕状态无法判定。）
- **SC-007**：停止后或中断条件消除后，参会者手动重新发起即可继续处理后续有效语音。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该标准时，一次停止或中断后能否继续已批准行为无法验收。）

## 验收场景

### IQA-001 范围内源语言形成实时中文字幕

- **追踪：** `INT-001`、`INT-003`、`INT-005`、`INT-006` / `US-001` / `FR-001`、`FR-003` / `NFR-001` / `AC-001`
- **前置条件：** 会议和实时字幕流程正在运行；浏览器语音输入及许可可用；客户指定 Azure Foundry STT 服务和客户指定的大模型可用；输入语言属于该 Azure Foundry STT 服务的覆盖范围。
- **操作：** 发言人提供可转写的会议语音。
- **预期结果：** 语音经客户指定 Azure Foundry STT 服务形成识别结果，并经客户指定的大模型翻译后，在会议期间持续显示对应的中文字幕。
- **必需证据：** 可核验的输入语言与内容、运行状态、所用客户指定服务约束得到满足，以及会议期间实际显示的中文字幕与发言含义的一致关系。

### IQA-002 全部自动检测语言的范围边界

- **追踪：** `INT-001`、`INT-004`、`INT-005`、`INT-006` / `US-002` / `FR-002`、`FR-003` / `AC-002`
- **前置条件：** 客户指定 Azure Foundry STT 服务和客户指定的大模型可用；已取得验收时该 Azure Foundry STT 服务实际可自动检测的完整源语言集合，并为各语言准备可转写语音。
- **操作：** 在运行中的实时字幕流程内，对集合中的每一种源语言分别提供对应语音，不预选源语言。
- **预期结果：** 每一种语言均由客户指定 Azure Foundry STT 服务自动检测，并经客户指定的大模型进入中文翻译字幕流程。
- **必需证据：** 权威完整语言集合、各语言输入标识、自动检测结果、所用客户指定服务约束得到满足及对应中文字幕。

### IQA-003 连续发言形成连续字幕

- **追踪：** `INT-001`、`INT-002`、`INT-006` / `US-001` / `FR-001`、`FR-003` / `NFR-001` / `AC-003`
- **前置条件：** 实时字幕流程正在运行，客户指定 Azure Foundry STT 服务和客户指定的大模型可用。
- **操作：** 发言人在同一流程中连续提供多个可区分的有效发言内容。
- **预期结果：** 会议期间持续出现与各段发言对应的中文字幕，不要求逐段重新发起，也不在停止后一次性批量出现。
- **必需证据：** 连续输入、流程持续运行、所用客户指定服务约束得到满足，以及会议期间连续出现的对应字幕。

### IQA-004 手动发起流程

- **追踪：** `INT-003` / `US-003` / `FR-004` / `SC-004` / `AC-004`（`closure`）
- **前置条件：** 流程处于未启动状态，浏览器采集条件可用。
- **操作：** 参会者手动发起实时字幕流程并提供有效语音。
- **预期结果：** 流程进入运行状态并开始处理发起后的语音。
- **必需证据：** 手动发起操作、状态转换和发起后语音开始被处理的可核验结果。

### IQA-005 手动停止流程

- **追踪：** `INT-003` / `US-003` / `FR-005` / `SC-005` / `AC-005`（`closure`）
- **前置条件：** 实时字幕流程正在运行。
- **操作：** 参会者手动停止流程，随后继续提供可转写语音。
- **预期结果：** 流程进入已停止状态，不采集停止后的语音，也不产生基于该语音的新字幕。
- **必需证据：** 手动停止操作、状态转换及停止后无新增采集和对应新字幕的结果。

### IQA-006 中断状态可见

- **追踪：** `INT-001`、`INT-003`、`INT-004`、`INT-005` / `US-001`、`US-002` / `FR-006` / `SC-006` / `AC-006`（`closure`）
- **前置条件：** 实时字幕流程正在运行。
- **操作：** 分别使语音采集、客户指定 Azure Foundry STT 服务的转写或语言检测、客户指定大模型的翻译无法继续。
- **预期结果：** 每种情况下均呈现当前无法继续产生字幕的状态，不将中断静默表现为正常处理。
- **必需证据：** 每类中断条件、对应可观察状态，以及中断期间未产生伪装成正常结果的字幕。

### IQA-007 手动重新发起流程

- **追踪：** `INT-001`、`INT-003`、`INT-004`、`INT-005` / `US-003` / `FR-007` / `SC-007` / `AC-007`（`closure`）
- **前置条件：** 流程已停止，或流程中断且中断条件已消除；客户指定 Azure Foundry STT 服务和客户指定的大模型可用。
- **操作：** 参会者手动重新发起流程并提供覆盖范围内的有效语音。
- **预期结果：** 流程进入运行状态，后续语音恢复转写、自动语言检测、中文翻译和字幕展示；不补发停止或中断期间内容。
- **必需证据：** 停止状态或中断条件消除、手动重新发起、状态转换、后续输入及其中文字幕。

## 验收标准

- **AC-001**：给定会议和流程正在运行、客户指定 Azure Foundry STT 服务与客户指定的大模型可用，当输入覆盖范围内的有效语音时，会议期间显示由该语音识别结果翻译得到的中文字幕。（`direct`）
- **AC-002**：给定验收时客户指定 Azure Foundry STT 服务实际可自动检测的完整语言集合，当逐一输入集合中各语言的有效语音且不预选源语言时，每种语言均被该服务自动检测并经客户指定的大模型进入中文翻译字幕流程。（`direct`）
- **AC-003**：给定流程持续运行，当连续提供多个可区分的有效发言内容时，会议期间持续出现对应中文字幕，而不是仅出现单次结果或停止后批量结果。（`direct`）
- **AC-004**：给定流程未启动且采集条件可用，当参会者手动发起并提供有效语音时，流程进入运行状态并开始处理发起后的语音。（`closure`）
- **AC-005**：给定流程正在运行，当参会者手动停止并继续提供语音时，产品不采集停止后的语音，也不产生基于该语音的新字幕。（`closure`）
- **AC-006**：给定流程正在运行，当采集、转写、语言检测或翻译无法继续时，参会者看到无法继续产生字幕的状态，且中断不被静默表现为正常处理。（`closure`）
- **AC-007**：给定流程已停止，或中断条件已消除，当参会者手动重新发起并提供后续有效语音时，后续语音重新形成中文字幕，不补发停止或中断期间内容。（`closure`）

## 测试策略

### 开发者验证

- 以 `FR-001` 至 `FR-007`、`NFR-001` 和 `AC-001` 至 `AC-007` 为边界，验证从浏览器语音采集，经客户指定 Azure Foundry STT 服务流式转写和自动语言检测、客户指定大模型中文翻译，到会议中字幕展示的完整用户流程；局部检查只能作为辅助证据。
- 覆盖正常流、连续多段发言、全部获批源语言范围、手动发起、手动停止、各处理阶段中断及手动重新发起。
- 保留可对应输入、状态、客户指定服务约束和用户可见输出的结果，不以构造的成功状态替代完整流程结果。
- 不扩展到范围外能力，也不把未批准的数值质量目标变成通过条件。

### Independent QA 验收

- 独立执行 `IQA-001` 至 `IQA-007`，按各场景的前置条件、操作、预期结果和必需证据判定。
- `IQA-001` 至 `IQA-003` 必须验证客户指定 Azure Foundry STT 服务和客户指定的大模型约束，并证明会议中的完整、连续用户流程，而非页面加载、单个处理步骤或会后结果。
- `IQA-002` 使用验收时可核验的客户指定 Azure Foundry STT 服务完整自动检测语言集合确定覆盖边界，不以抽样通过替代全部语言范围。
- 手动发起、停止、中断和手动重新发起分别判定，不得以正常路径通过代替其证据。

### 总体通过与失败标准

- **通过**：`IQA-001` 至 `IQA-007` 全部满足各自预期结果和必需证据，客户指定 Azure Foundry STT 服务与客户指定大模型约束得到证明，且没有观察到与 `FR-001` 至 `FR-007`、`NFR-001` 或业务不变量冲突的行为。
- **失败**：任一必需场景未执行、缺少必需证据、任一验收标准不满足、未满足客户指定服务约束，或结果仅证明局部步骤而未证明相应完整用户流程。
- 未获批准的数值指标、额外质量等级和范围外能力不参与通过或失败判定。

## 假设、依赖与范围外边界

### 假设

- “中文”沿用 Intent 的原始表述，不在本阶段默认细分书写体系或地区变体。
- 单次验收中的覆盖语言集合以验收开始时可核验的客户指定 Azure Foundry STT 服务实际自动检测能力为准，不固定或扩大语言集合。
- 未批准同时多人重叠发言、单段发言内混用多种语言或会议中途保留历史字幕的额外行为，这些情况不作为本次验收义务。

### 依赖

- 客户指定 Azure Foundry STT 服务实际能够支持所要求的流式语音转写和源语言自动检测。
- 客户指定的大模型实际能够支持将识别结果持续翻译为中文。
- 可接受源语言范围依赖验收时客户指定 Azure Foundry STT 服务实际支持的自动检测语言范围。
- 浏览器设备具备可用语音输入且获得采集许可。

### 范围外边界

- 会后全文、录音、字幕归档、导出或停止及中断期间内容补发。
- 中文以外的目标字幕语言。
- 会议管理、参会者管理或 Teams 集成。
- 人工翻译、人工校订或人工审核。
- 未经批准的性能数值、可靠性等级、安全或隐私产品行为、可访问性等级及合规目标。
