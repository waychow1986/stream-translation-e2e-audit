# 实时流式翻译产品规格

## 产品目标与边界

本规格将已批准的 `INT-001` 至 `INT-006` 转化为可观察、可验收的产品行为：会议期间，浏览器采集发言人语音，持续形成转写内容，自动检测源语言，将内容持续翻译为中文并实时显示为字幕，使需要中文字幕的参会者及时理解发言。

根据产品批准反馈确认的服务能力边界，产品行为调整为：参会者在每次发起实时字幕前，从客户指定 Azure Foundry STT 服务支持的语言中选择一至十种候选源语言；运行期间产品在该候选范围内自动检测实际源语言，无需参会者逐段指定。此调整保留自动检测及服务支持语言可按会议覆盖的业务目标，同时消除单次流程要求覆盖完整语言集合的不可实现义务。

范围限于会议中的浏览器语音采集、实时流式转写、候选源语言范围选择、范围内自动检测、中文翻译和字幕展示。Teams 仅为连续字幕体验参照，不属于集成对象。会后全文、录音、字幕归档或导出，中文以外的目标语言，会议或参会者管理，以及人工翻译、校订或审核均不在范围内。

`INT-006` 的客户约束保持不变：语音转文本与源语言自动检测使用客户指定 Azure Foundry STT 服务，中文翻译使用客户指定的大模型。本规格不选择架构、接口、模型、协议、运行环境或其他实现细节。

## 参与者与权限

- **发言人**：提供会议语音；不承担字幕控制职责，也没有获批准的管理权限。
- **需要中文字幕的参会者**：选择本次流程的候选源语言范围，查看中文字幕，并可手动发起、停止和重新发起实时字幕流程。
- **浏览器设备许可**：浏览器取得语音输入许可是采集前置条件；它不是产品角色或账户权限。
- 当前没有获批准的账户体系、角色分级、会议管理或参会者管理要求。

## 用户故事

### US-001 会议中查看连续中文字幕（优先级：未指定）

作为需要中文字幕的参会者，我希望在发言人讲话期间持续看到由其语音转写并翻译得到的中文字幕，以便在会议进行时理解发言，而不是会后才获得结果。（`INT-001`、`INT-002`、`INT-003`、`INT-005`，`direct`）

### US-002 为会议设置候选源语言并自动检测（优先级：未指定）

作为需要中文字幕的参会者，我希望在发起前从客户指定服务支持的语言中选择本次会议可能使用的一至十种候选源语言，并让产品在运行期间自动检测实际源语言，以便在已确认的服务能力内覆盖本次会议。（`INT-001`、`INT-004`、`INT-005`，`clarification`，来源：已解决的 `PQ-001`）

### US-003 控制实时字幕流程边界（优先级：未指定）

作为需要中文字幕的参会者，我希望能够手动发起、停止并在停止或中断条件消除后重新发起实时字幕流程，以便明确浏览器何时开始和结束采集，并继续处理后续发言。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该控制时，浏览器采集没有可判定的启停边界，一次停止或中断后能否处理后续发言也不确定。）

## 功能需求

- **FR-001**：实时字幕流程处于运行状态时，产品必须通过浏览器采集发言人语音，并使用客户指定 Azure Foundry STT 服务持续形成流式转写结果。（`INT-003`、`INT-006`，`direct`）
- **FR-002**：每次发起或重新发起前，产品必须允许参会者从客户指定 Azure Foundry STT 服务当时支持的源语言中选择一至十种，作为该次流程的候选源语言范围；范围为空、包含服务不支持的语言或超过十种时不得发起。（`INT-001`、`INT-004`、`INT-006`，`clarification`，来源：`PQ-001`）
- **FR-003**：流程运行期间，产品必须使用客户指定 Azure Foundry STT 服务在已选候选范围内自动检测输入语音的实际源语言，不要求参会者逐段指定实际语言。（`INT-001`、`INT-004`、`INT-006`，`clarification`，来源：`PQ-001`）
- **FR-004**：产品必须使用客户指定的大模型将候选范围内源语言的识别结果翻译为中文，并在会议期间以字幕形式持续展示。（`INT-001`、`INT-005`、`INT-006`，`direct`）
- **FR-005**：参会者完成有效候选范围选择并手动发起实时字幕流程后，产品必须进入运行状态并开始执行 `FR-001`、`FR-003` 和 `FR-004`。（`INT-003`、`INT-004`，`closure`；缺少明确发起条件时，浏览器何时按所选范围开始采集和处理会议语音不确定。）
- **FR-006**：参会者手动停止实时字幕流程后，产品必须停止采集，并且不得再基于停止后的语音产生新字幕。（`INT-003`，`closure`；缺少停止行为时，浏览器采集没有终止边界。）
- **FR-007**：当语音无法被采集，或转写、语言检测、翻译中的任一步骤无法继续时，产品必须呈现当前无法继续产生字幕的可观察状态，不得将中断静默表现为仍在正常处理。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该状态时，参会者无法区分正常等待与流程中断。）
- **FR-008**：停止后，或中断条件消除后，参会者必须能够确认或调整候选源语言范围并手动重新发起流程；后续有效语音按 `FR-001`、`FR-003` 和 `FR-004` 处理，不要求补发停止或中断期间的内容。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少重新发起行为时，一次停止或中断后能否继续服务后续发言不确定。）

## 产品质量要求

- **NFR-001**：对流程运行期间连续出现的有效语音，字幕必须在会议仍在进行时持续产生，而非仅生成单次结果或延迟到会后批量提供。（`INT-001`、`INT-002`，`direct`）

除上述实时、连续体验外，当前没有获批准的额外产品质量要求或数值质量目标。

## 领域术语

- **实时字幕流程**：从参会者完成有效候选范围选择并手动发起，到参会者手动停止或发生中断期间，将语音持续转写、翻译并展示为字幕的业务过程。
- **候选源语言范围**：参会者在每次发起或重新发起前，从客户指定 Azure Foundry STT 服务当时支持的源语言中选择的一至十种语言。
- **实际源语言**：产品在候选源语言范围内自动检测出的当前输入语音语言。
- **有效语音**：具备采集条件，能够被客户指定 Azure Foundry STT 服务转写，且实际源语言属于当前候选范围的语音。
- **识别结果**：客户指定 Azure Foundry STT 服务由输入语音形成、可供翻译的转写内容。
- **中断**：采集、转写、语言检测或翻译无法继续，因而不能继续产生字幕的状态。

## 前置条件与触发条件

- 会议正在进行，发言人能够提供语音，需要中文字幕的参会者已进入浏览器中的实时字幕使用场景。
- 浏览器具备可用的语音输入，并已获得采集所需的设备许可。
- 客户指定 Azure Foundry STT 服务和客户指定的大模型可用于本次流程。
- 参会者已从客户指定 Azure Foundry STT 服务当时支持的语言中选择一至十种候选源语言。
- 参会者手动发起触发采集、转写、范围内语言检测、中文翻译和字幕展示；手动停止触发终止；停止后或中断条件消除后，确认或调整候选范围并手动重新发起，触发后续语音处理。

## 行为模型

### US-001 会议中查看连续中文字幕

- **正常路径**：流程运行期间，产品持续采集、转写、在候选范围内检测源语言、翻译为中文并展示字幕。（`FR-001`、`FR-003`、`FR-004`、`NFR-001`、`AC-001`、`AC-004`）
- **替代路径**：同一流程中的后续有效语音继续形成后续字幕，无需逐段重新发起。（`NFR-001`、`AC-004`）
- **边界路径**：参会者停止后，不采集停止后的语音，也不产生基于该语音的新字幕。（`FR-006`、`AC-006`）
- **错误路径**：任一处理步骤无法继续时，呈现流程中断状态。（`FR-007`、`AC-007`）
- **恢复路径**：条件消除后，参会者确认或调整候选范围并重新发起，后续有效语音恢复处理，不补发中断期间内容。（`FR-008`、`AC-008`）

### US-002 为会议设置候选源语言并自动检测

- **正常路径**：参会者选择一至十种服务支持语言并发起；输入其中任一语言的有效语音时，产品自动检测实际语言并输出中文字幕。（`FR-002` 至 `FR-004`、`AC-002`、`AC-003`）
- **替代路径**：同一流程中实际源语言在已选候选范围内变化时，无需逐段手动指定，产品继续自动检测。（`FR-003`、`AC-003`）
- **边界路径**：候选范围为空、包含不受支持的语言或超过十种时，产品不发起流程，并允许参会者修正选择。（`FR-002`、`AC-002`）
- **错误与恢复路径**：输入语言不在候选范围内或无法检测时进入中断；参会者可在条件消除后确认或调整候选范围并重新发起。（`FR-007`、`FR-008`、`AC-007`、`AC-008`）

### US-003 控制实时字幕流程边界

- **发起路径**：未运行且候选范围有效时，参会者手动发起，流程进入运行状态并处理后续语音。（`FR-005`、`AC-005`）
- **停止路径**：运行或中断时，参会者手动停止，流程进入已停止状态。（`FR-006`、`AC-006`）
- **重新发起路径**：已停止时或中断条件消除后，参会者确认或调整有效候选范围并手动重新发起，流程进入运行状态。（`FR-008`、`AC-008`）

## 业务状态、业务数据规则与不变量

### 业务状态

1. **未启动**：尚未完成有效候选范围选择并手动发起，不采集语音。
2. **运行中**：已按有效候选范围手动发起，持续接收并处理语音，可产生中文字幕。
3. **中断**：采集、转写、语言检测或翻译无法继续，并呈现可观察状态。
4. **已停止**：已手动停止，不再采集语音或产生基于停止后语音的新字幕。

允许的转换为：未启动在候选范围有效时经手动发起到运行中；运行中到中断或经手动停止到已停止；中断经手动停止到已停止，或在条件消除并确认或调整有效候选范围后经手动重新发起到运行中；已停止经确认或调整有效候选范围并手动重新发起到运行中。

### 业务数据规则与不变量

- 每条中文字幕必须源自流程运行期间采集的语音及其识别结果。
- 字幕目标语言固定为中文。
- 每次流程的候选源语言范围必须包含一至十种客户指定 Azure Foundry STT 服务当时支持的语言；实际源语言由产品在该范围内自动检测。
- 转写和源语言自动检测必须使用客户指定 Azure Foundry STT 服务；中文翻译必须使用客户指定的大模型。
- 字幕仅承担会议期间实时展示；不承诺会后保留、归档、导出或补发。
- 未启动、已停止或中断状态下不得将流程表现为仍在正常采集并产生字幕。

## 错误与恢复行为

- 候选范围为空、超过十种或包含客户指定 Azure Foundry STT 服务当时不支持的语言时，不得发起流程；参会者可修正后再次发起。
- 浏览器未取得语音输入许可、语音输入不可用或采集失败时，必须呈现无法继续产生字幕的状态。
- 客户指定 Azure Foundry STT 服务无法继续转写或检测源语言，或客户指定的大模型无法继续翻译时，必须呈现中断状态；不得以未经处理的内容冒充中文字幕。
- 对实际源语言不在当前候选范围内或无法检测的语音，不要求生成中文字幕，按无法继续处理的中断行为处理。
- 条件消除后，参会者确认或调整有效候选范围并手动重新发起，处理后续有效语音；不承诺恢复或补发停止或中断期间的内容。

## 安全、隐私与可访问性行为

宪章“三、数据安全”要求保护会议内容和凭据，但未直接规定可从已批准 Intent 派生的具体用户可见产品行为。当前没有获批准的额外安全、隐私或可访问性产品要求，因此本规格不新增 NFR、等级、权限行为或验收门禁。

## 性能、可靠性与其他质量边界

已批准范围仅要求 `NFR-001` 所述会议期间持续产生字幕的可观察结果，未批准具体响应时限、刷新频率、准确率、可用率、恢复时限、并发容量或正式质量等级。

## 成功标准

- **SC-001**：会议进行期间，当前候选范围内的有效发言形成持续展示的中文字幕，使参会者无需等待会后结果即可阅读。（`INT-001`、`INT-002`、`INT-005`，`direct`）
- **SC-002**：参会者能够从客户指定 Azure Foundry STT 服务当时支持的语言中为每次流程选择一至十种候选源语言；无效范围不能启动。（`INT-001`、`INT-004`，`clarification`，来源：`PQ-001`）
- **SC-003**：流程运行期间，候选范围内的实际源语言由产品自动检测，不要求参会者逐段指定。（`INT-001`、`INT-004`，`clarification`，来源：`PQ-001`）
- **SC-004**：连续有效发言产生连续字幕，而非只产生单次结果或会后批量结果。（`INT-002`，`direct`）
- **SC-005**：候选范围有效且参会者手动发起后，流程进入运行状态并开始处理后续有效语音。（`INT-003`、`INT-004`，`closure`；缺少该标准时，开始采集和应用候选范围的边界无法验收。）
- **SC-006**：参会者手动停止后，流程不再采集后续语音或产生基于该语音的新字幕。（`INT-003`，`closure`；缺少该标准时，浏览器采集的终止边界无法验收。）
- **SC-007**：流程无法继续时，参会者能够区分中断与正常处理。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该标准时，错误情况下的实时字幕状态无法判定。）
- **SC-008**：停止后或中断条件消除后，参会者确认或调整有效候选范围并重新发起，即可继续处理后续有效语音。（`INT-001`、`INT-003` 至 `INT-005`，`closure`；缺少该标准时，一次停止或中断后能否继续已批准行为无法验收。）

## 验收场景

### IQA-001 候选范围内语音形成实时中文字幕

- **追踪：** `INT-001`、`INT-003`、`INT-005`、`INT-006` / `US-001` / `FR-001`、`FR-004` / `NFR-001` / `AC-001`
- **前置条件：** 会议和实时字幕流程正在运行；所选候选范围有效；浏览器语音输入及许可、客户指定服务均可用。
- **操作：** 发言人以候选范围内的一种语言提供可转写的会议语音。
- **预期结果：** 会议期间持续显示与发言含义一致的中文字幕。
- **必需证据：** 可核验的输入语言与内容、运行状态、客户指定服务约束得到满足，以及会议期间实际显示的中文字幕。

### IQA-002 候选源语言范围边界

- **追踪：** `INT-001`、`INT-004`、`INT-006` / `US-002` / `FR-002` / `SC-002` / `AC-002`（`clarification`，来源：`PQ-001`）
- **前置条件：** 能够确认客户指定 Azure Foundry STT 服务当时支持的源语言。
- **操作：** 分别尝试以一种、十种、空范围、超过十种及包含不受支持语言的范围发起流程。
- **预期结果：** 一种和十种受支持语言组成的范围可以发起；其余范围不能发起，并可修正。
- **必需证据：** 每次选择的语言范围、服务支持关系、发起操作及对应可观察结果。

### IQA-003 候选范围内自动检测

- **追踪：** `INT-001`、`INT-004`、`INT-005`、`INT-006` / `US-002` / `FR-003`、`FR-004` / `SC-003` / `AC-003`（`clarification`，来源：`PQ-001`）
- **前置条件：** 流程按包含多种语言的有效候选范围运行，客户指定服务可用。
- **操作：** 不逐段指定实际语言，分别输入候选范围内各语言的有效语音。
- **预期结果：** 每种输入均在候选范围内被自动检测，并进入中文翻译字幕流程。
- **必需证据：** 候选范围、各输入语言与内容、自动检测结果及对应中文字幕。

### IQA-004 连续发言形成连续字幕

- **追踪：** `INT-001`、`INT-002`、`INT-006` / `US-001` / `FR-001`、`FR-004` / `NFR-001` / `AC-004`
- **前置条件：** 实时字幕流程按有效候选范围运行，客户指定服务可用。
- **操作：** 发言人在同一流程中连续提供多个可区分的有效发言内容。
- **预期结果：** 会议期间持续出现与各段发言对应的中文字幕，不要求逐段重新发起，也不在停止后一次性批量出现。
- **必需证据：** 连续输入、流程持续运行、客户指定服务约束得到满足，以及会议期间连续出现的对应字幕。

### IQA-005 手动发起流程

- **追踪：** `INT-003`、`INT-004` / `US-003` / `FR-005` / `SC-005` / `AC-005`（`closure`）
- **前置条件：** 流程处于未启动状态，候选范围及浏览器采集条件有效。
- **操作：** 参会者手动发起并提供有效语音。
- **预期结果：** 流程进入运行状态并开始处理发起后的语音。
- **必需证据：** 有效候选范围、手动发起操作、状态转换和发起后语音开始被处理的结果。

### IQA-006 手动停止流程

- **追踪：** `INT-003` / `US-003` / `FR-006` / `SC-006` / `AC-006`（`closure`）
- **前置条件：** 实时字幕流程正在运行。
- **操作：** 参会者手动停止流程，随后继续提供可转写语音。
- **预期结果：** 流程进入已停止状态，不采集停止后的语音，也不产生基于该语音的新字幕。
- **必需证据：** 手动停止操作、状态转换及停止后无新增采集和对应新字幕的结果。

### IQA-007 中断状态可见

- **追踪：** `INT-001`、`INT-003`、`INT-004`、`INT-005` / `US-001`、`US-002` / `FR-007` / `SC-007` / `AC-007`（`closure`）
- **前置条件：** 实时字幕流程正在运行。
- **操作：** 分别使语音采集、转写、语言检测或翻译无法继续，并输入候选范围外或无法检测的语音。
- **预期结果：** 每种情况下均呈现当前无法继续产生字幕的状态，不将中断静默表现为正常处理。
- **必需证据：** 每类中断条件、对应可观察状态，以及中断期间未产生伪装成正常结果的字幕。

### IQA-008 手动重新发起流程

- **追踪：** `INT-001`、`INT-003`、`INT-004`、`INT-005` / `US-003` / `FR-008` / `SC-008` / `AC-008`（`closure`）
- **前置条件：** 流程已停止，或流程中断且中断条件已消除；客户指定服务可用。
- **操作：** 参会者确认或调整为有效候选范围，手动重新发起并提供范围内有效语音。
- **预期结果：** 流程进入运行状态，后续语音恢复转写、范围内语言检测、中文翻译和字幕展示；不补发停止或中断期间内容。
- **必需证据：** 停止状态或中断条件消除、有效候选范围、手动重新发起、状态转换、后续输入及其中文字幕。

## 验收标准

- **AC-001**：给定会议和流程正在运行且客户指定服务可用，当输入当前候选范围内的有效语音时，会议期间显示由该语音识别结果翻译得到的中文字幕。（`INT-001`、`INT-003`、`INT-005`、`INT-006`，`direct`）
- **AC-002**：给定客户指定 Azure Foundry STT 服务当时支持的语言，当参会者选择一至十种受支持语言时可以发起；候选范围为空、超过十种或包含不受支持语言时不能发起，并可修正。（`INT-001`、`INT-004`、`INT-006`，`clarification`，来源：`PQ-001`）
- **AC-003**：给定流程按包含多种语言的有效候选范围运行，当不逐段指定实际语言而分别输入范围内各语言的有效语音时，每种语言均被自动检测并进入中文翻译字幕流程。（`INT-001`、`INT-004`、`INT-005`、`INT-006`，`clarification`，来源：`PQ-001`）
- **AC-004**：给定流程持续运行，当连续提供多个可区分的有效发言内容时，会议期间持续出现对应中文字幕，而不是仅出现单次结果或停止后批量结果。（`INT-001`、`INT-002`，`direct`）
- **AC-005**：给定流程未启动、候选范围和采集条件有效，当参会者手动发起并提供有效语音时，流程进入运行状态并开始处理发起后的语音。（`INT-003`、`INT-004`，`closure`）
- **AC-006**：给定流程正在运行，当参会者手动停止并继续提供语音时，产品不采集停止后的语音，也不产生基于该语音的新字幕。（`INT-003`，`closure`）
- **AC-007**：给定流程正在运行，当采集、转写、语言检测或翻译无法继续时，参会者看到无法继续产生字幕的状态，且中断不被静默表现为正常处理。（`INT-001`、`INT-003` 至 `INT-005`，`closure`）
- **AC-008**：给定流程已停止，或中断条件已消除，当参会者确认或调整有效候选范围、手动重新发起并提供后续有效语音时，后续语音重新形成中文字幕，不补发停止或中断期间内容。（`INT-001`、`INT-003` 至 `INT-005`，`closure`）

## 假设、依赖与范围外边界

### 假设

- “中文”沿用 Intent 的原始表述，不在本阶段默认细分书写体系或地区变体。
- 客户指定 Azure Foundry STT 服务“当时支持”的语言以每次发起时可确认的服务能力为准；本规格不固定或扩大其语言清单。
- 未批准同时多人重叠发言、单段发言内混用多种语言或会议中途保留历史字幕的额外行为，这些情况不作为本次验收义务。

### 依赖

- 客户指定 Azure Foundry STT 服务实际支持所要求的流式语音转写，以及在每次一至十种候选源语言范围内进行自动检测。
- 客户指定的大模型实际支持将识别结果持续翻译为中文。
- 浏览器设备具备可用语音输入且获得采集许可。

### 范围外边界

- 单次流程同时接受超过十种候选源语言，或在没有有效候选范围时猜测源语言。
- 会后全文、录音、字幕归档、导出或停止及中断期间内容补发。
- 中文以外的目标字幕语言。
- 会议管理、参会者管理或 Teams 集成。
- 人工翻译、人工校订或人工审核。
- 未经批准的性能数值、可靠性等级、安全或隐私产品行为、可访问性等级及合规目标。
