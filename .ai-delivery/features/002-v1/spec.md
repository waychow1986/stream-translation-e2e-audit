# 实时流式翻译产品规格

## 产品目标与边界

本规格将已批准的 INT-001 至 INT-008 转化为 V1 可观察、可验收的产品行为：在会议发言进行期间，从浏览器采集英语语音，自动检测源语言，持续转写并将结果翻译为中文字幕，使会议参与者能够同步理解发言。

范围限于英语到中文的会议实时流式翻译。除语音采集、源语言自动检测、流式转写、流式翻译和中文字幕呈现外，不包含其他会议能力、其他源语言或其他目标语言，也不要求单独展示原文转写。

## 参与者与权限

- **会议发言人**：提供待处理的英语语音；其使用的浏览器须能够采集该语音。发言人不需要手动指定源语言。
- **会议参与者**：查看持续呈现的中文字幕，以理解英语发言。
- **权限边界**：已批准 Intent 未定义身份、角色管理或差异化访问控制；本规格不新增此类权限行为。

## 用户故事

### US-001 采集并转写会议发言（P1）

作为英语会议发言人，我希望发言语音在浏览器中被持续采集并流式转写，以便发言可在进行期间进入翻译流程。（INT-004）

### US-002 自动识别 V1 源语言（P1）

作为会议参与者，我希望系统自动检测发言源语言且无需人工选择，以便 V1 范围内的英语发言可以进入中文翻译流程。（INT-005、INT-008）

### US-003 持续阅读中文字幕（P1）

作为通过中文理解发言的会议参与者，我希望在英语发言进行期间持续看到与发言含义及先后顺序相符的中文字幕，以便同步理解会议内容。（INT-001、INT-002、INT-003、INT-006）

## 功能需求

- **FR-001**：产品必须通过浏览器持续采集会议发言人的语音，并在发言进行期间对采集内容进行流式转写。
- **FR-002**：产品必须自动检测采集语音的源语言，不要求发言人或会议参与者手动选择源语言。
- **FR-003**：V1 必须以检测为英语的发言作为支持的源语言，并以中文作为翻译目标语言。
- **FR-004**：产品必须将流式转写得到的英语内容持续翻译为中文，并在发言进行期间持续呈现为字幕，而不是只在整段发言结束后一次性给出全部结果。
- **FR-005**：连续字幕必须保持发言内容的先后顺序，且中文内容应表达对应英语发言的含义。

## 产品质量要求

- **NFR-001**：字幕体验必须具有发言期间可观察的连续性；对包含连续多个可区分语义片段的英语发言，较早片段的中文字幕应在后续片段仍在发言时可见。

除上述由 INT-002、INT-003 和 INT-006 直接要求的连续实时体验外，当前没有获批准的额外性能、可靠性、安全、隐私、可访问性或合规质量等级及数值阈值。

## 领域术语

- **会议发言**：会议发言人通过可采集语音表达的内容。
- **流式转写**：在发言持续进行时逐步形成语音识别结果，而非等待整段发言结束后才开始形成结果。
- **源语言自动检测**：产品依据采集语音识别源语言，无需用户手动指定；V1 支持范围仅为英语。
- **流式翻译**：随着转写结果形成，逐步产生对应的中文内容。
- **中文字幕**：向会议参与者可见、用于表达对应英语发言含义的中文文本。
- **连续字幕体验**：字幕随发言过程逐步出现，并保持对应内容的先后顺序。

## 前置条件与触发条件

- 浏览器能够采集会议发言人的语音。
- 客户指定的 Azure Foundry 语音转文本服务与大模型能力可用于本次语音处理和翻译。
- 待验收发言使用 V1 支持的英语。
- 当浏览器开始采集会议发言人的英语语音时，实时流式转写、自动检测、翻译与字幕呈现流程被触发。

## 行为模型

### US-001 语音采集与流式转写

- **正常路径**：浏览器采集持续的英语发言；发言尚未结束时，转写结果已随已采集内容逐步形成。（FR-001，AC-001）
- **边界路径**：尚未采集到语音内容时，不存在可供转写和翻译的发言内容；采集到内容后进入正常路径。（FR-001，AC-001）
- **错误路径**：浏览器无法采集语音时，FR-001 无法成立，本次端到端验收失败。

### US-002 英语自动检测

- **正常路径**：产品根据采集语音自动检测出英语并继续翻译，无需用户选择源语言。（FR-002、FR-003，AC-002）
- **范围边界**：非英语源语言不属于 V1 验收范围，不据此推导其他语言的识别、提示或翻译行为。（FR-003）
- **错误路径**：V1 英语发言未被自动识别并进入翻译流程时，本次验收失败。

### US-003 中文字幕持续呈现

- **正常路径**：在一段包含多个可区分语义片段的英语发言中，产品依次形成转写与中文翻译，较早片段的中文字幕在后续片段仍在发言时可见，后续字幕保持发言顺序并表达对应含义。（FR-004、FR-005、NFR-001，AC-003、AC-004）
- **替代路径**：发言结束时，已在发言期间出现的字幕仍可用于确认本次流程完成；本规格不要求额外的会后记录能力。（FR-004，AC-003）
- **错误路径**：仅在整段发言结束后一次性显示全部翻译、字幕顺序与发言顺序不符，或字幕不表达对应发言含义，均不满足验收要求。

## 业务状态、业务数据规则与不变量

业务流程按 `未采集 → 采集中 → 转写形成中 → 中文翻译呈现中 → 本次发言结束` 描述可观察进展；流式处理期间，转写形成与中文翻译呈现可以随发言推进而持续发生。

- 输入业务数据是浏览器采集的会议语音；V1 可验收源语言为英语。
- 输出业务数据是与已转写英语内容对应的中文字幕；目标语言为中文。
- 字幕片段顺序不得颠倒对应发言内容的先后顺序。
- 字幕必须源自本次采集语音的转写与翻译，不得将无对应发言的内容作为本次翻译结果。
- V1 的英语源语言边界与中文目标语言边界在整个流程中保持不变。

## 错误与恢复行为

- 浏览器无法采集语音、英语未被自动检测、指定依赖不可用、未在发言期间形成中文字幕、字幕顺序错误或字幕不表达对应发言含义时，对应验收场景判定失败，不得用页面可访问或发言结束后的批量结果替代。
- 已批准 Intent 未规定面向用户的错误提示、自动重试、断点续接或中断内容保留行为，当前没有获批准的额外要求。
- 故障排除并重新满足前置条件后，可以重新执行完整用户流程；重新执行不代表已批准自动恢复或续接能力。

## 安全、隐私与可访问性行为

已批准 Intent 未定义额外的安全、隐私或可访问性用户行为、等级或验收目标；当前没有获批准的额外要求。会议内容和凭据仍受 Constitution“三、数据安全”的治理约束，但该原则未给出可在本规格中新增的具体产品行为。

## 性能、可靠性与其他质量边界

“实时”和“连续”的产品边界由 NFR-001 以发言期间是否已出现较早语义片段字幕来判定，不额外引入时间数值。当前没有获批准的额外响应时限、吞吐量、并发量、可用率、恢复时限、准确率百分比或正式质量等级。

## 成功标准

- **SC-001**：英语会议发言在进行期间即产生表达对应含义的中文字幕，而非只在整段发言结束后一次性产生全部结果。
- **SC-002**：英语源语言由产品自动检测，完整流程无需用户手动选择源语言。
- **SC-003**：对包含多个可区分语义片段的发言，中文字幕按发言先后顺序持续出现，并使中文阅读者能够理解对应内容。
- **SC-004**：端到端结果由浏览器语音采集、客户指定的实际语音转文本能力和大模型能力共同完成，不以替代结果冒充已批准流程。

## 验收场景

### IQA-001 英语发言期间持续出现中文字幕

- **追踪：** INT-001、INT-002、INT-003、INT-004、INT-006 / US-001、US-003 / FR-001、FR-004、FR-005 / NFR-001 / AC-001、AC-003、AC-004
- **前置条件：** 在可进行完整流程的部署环境中，浏览器能够采集语音，客户指定的实际依赖可用；准备一段合成英语语音，其中按顺序包含多个含义明确、彼此可区分的语义片段。
- **操作：** 通过浏览器输入并播放该英语语音；在后续语义片段仍在播放时观察字幕，并继续观察至整段发言结束。
- **预期结果：** 后续片段仍在播放时，较早片段对应的中文字幕已经可见；后续中文字幕继续按发言顺序出现，且各字幕表达对应英语片段的含义。任一条件不成立即失败。
- **必需证据：** 带有输入语音进度和可见字幕变化的端到端执行记录，以及输入语义片段与中文结果的对应记录。

### IQA-002 自动检测英语并翻译为中文

- **追踪：** INT-005、INT-008 / US-002 / FR-002、FR-003 / AC-002
- **前置条件：** 完整流程可用；准备一段含义明确的合成英语语音；流程开始前不手动指定源语言。
- **操作：** 通过浏览器采集该语音并观察完整处理结果。
- **预期结果：** 产品自动将源语言检测为英语并产生表达输入含义的中文字幕；若需要用户手动选择源语言、未识别英语或输出目标不是中文，则失败。
- **必需证据：** 显示未进行源语言手动选择、英语输入和对应中文字幕结果的端到端执行记录。

### IQA-003 已批准完整用户流程使用实际依赖

- **追踪：** INT-004、INT-005、INT-006、INT-007、INT-008 / US-001、US-002、US-003 / FR-001、FR-002、FR-003、FR-004、FR-005 / NFR-001 / AC-001、AC-002、AC-003、AC-004
- **前置条件：** 部署环境已连接客户指定的实际 Azure Foundry 语音转文本服务与大模型能力；准备包含多个可区分语义片段的合成英语语音。
- **操作：** 以黑盒方式从浏览器语音采集开始，执行自动检测、流式转写、流式翻译和中文字幕显示的完整流程。
- **预期结果：** 实际完整流程满足 AC-001 至 AC-004；页面加载、模拟依赖结果或局部处理成功不能单独构成通过证据。
- **必需证据：** 一次完整执行中输入、发言期间字幕变化、最终字幕语义和实际依赖调用结果可关联核验的记录，且不包含凭据。

## 验收标准

- **AC-001**：浏览器采集英语发言时，发言结束前已经形成与已采集语音对应的流式转写处理结果并进入字幕流程。
- **AC-002**：未手动选择源语言时，产品自动检测英语，并将翻译目标保持为中文。
- **AC-003**：对包含多个可区分语义片段的英语发言，较早片段的中文字幕在后续片段仍在发言时可见，且后续字幕继续按发言顺序呈现。
- **AC-004**：可见中文字幕表达对应英语发言片段的含义；仅有原文转写、非中文输出、无关内容或语义不对应均不通过。

## 测试策略

测试以已批准的英语到中文完整用户流程为边界，使用含义明确、可重复的合成英语语音，覆盖正常流式路径、自动检测、发言期间连续呈现、顺序与语义对应，以及依赖或关键行为缺失时的失败判定。不扩展其他源语言、会后记录、错误提示、恢复机制或未获批准的质量目标。

### 开发者验证

- 分别验证语音采集、流式转写、自动检测英语、中文翻译和字幕渐进呈现，并确认组合后仍满足 AC-001 至 AC-004。
- 使用至少包含多个可区分语义片段的合成英语语音，核对较早片段在后续发言期间可见、字幕顺序和语义对应。
- 验证非完整结果不会误判通过：仅页面可访问、仅有原文转写、仅在发言结束后批量显示、非中文输出、顺序颠倒或语义不对应均应产生明确失败。
- 验证记录不得包含服务凭据或其他秘密。

### Independent QA 验收

Independent QA 在真实部署环境中以黑盒方式执行 IQA-001 至 IQA-003，使用实际集成服务而非 Mock，并优先使用合成英语语音。QA 依据可见字幕进展、输入与输出语义对应关系、顺序及实际依赖结果进行判定；无需真人录音或真实业务会议数据。

### 总体通过与失败标准

只有 IQA-001、IQA-002 和 IQA-003 全部通过，且 AC-001 至 AC-004 均有同一次或可关联的完整流程证据时，本规格验收通过。任一场景失败、任一验收标准缺少证据、使用 Mock 替代实际集成服务，或仅以页面加载和局部检查作为证据时，总体失败。

## 假设、依赖与范围外边界

- **假设**：用于判定语义对应的验收语音采用含义明确、可用常见中文直接表达的英语语句；这是为了消除判定表述差异，不设定新的翻译准确率指标。
- **假设**：中文字幕可包含表达原意所需的数字、标点和专有名词，不将“中文”解释为只能出现中文字符。
- **依赖**：浏览器具备会议语音采集条件，客户指定的 Azure Foundry 语音转文本服务和大模型能力可用；凭据与部署条件由后续执行环境提供。
- **范围外**：英语以外源语言、中文以外目标语言、原文字幕、会后转录或字幕记录、说话人区分、身份与角色管理、人工翻译、错误提示样式、自动重试、断点续接，以及 Intent 未批准的其他会议能力。
- **质量边界**：除 NFR-001 外，不推导额外性能、可靠性、安全、隐私、可访问性、合规目标、数值阈值或正式等级。
